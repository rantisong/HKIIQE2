# 团队模块设计方案（已按确认意见修订）

## 一、需求摘要

- **顶部三个统计**（针对当前用户**全部下属**，多层级）：  
  - **团队**：下属总人数。  
  - **合资格**：下属中通过**科目一且科目三**的人数。  
  - **全牌照**：下属中通过**科目 1～5 全部**的人数。  
- **邀请我的团队长**：有上级时展示邀请人（团队长），点击进入「所属团队」页；**无上级时不展示该整块**。  
- **团队成员**：当前用户**直接邀请**的用户列表；可点击某成员进入其「下属团队」页，**页面结构与现有团队页一致**。  
- **成员展示**：有下属则显示其团队总人数 + 右箭头可点击；无下属则不显示人数与箭头。  
- **邀请码**：注册时自动生成 6 位数字+字母邀请码，即「我的团队邀请码」；**团队与用户邀请码关联**（见下）。

---

## 二、与现有系统的关系

### 2.1 已有能力

| 能力 | 说明 |
|------|------|
| 用户与邀请码 | `users` 在 `user_getUserInfo` 中已为新用户生成并写入 `inviteCode`（6 位数字+字母），唯一性已保证。 |
| 练习/答题 | `records` 等仅用于练习模块，**与团队模块的合资格/全牌照统计无关**。 |

### 2.2 合资格 / 全牌照数据来源（已确认）

- **不依赖练习或真题答题记录**。  
- 合资格、全牌照统计来源于**用户手动提交的真实考试成绩**。  
- 真实考试通过情况由**用户自行在「我的」模块中录入/维护**（入口与具体交互后续在「我的」模块实现）。  
- 团队模块仅读取「用户真实考试通过情况」做统计，数据结构见下文「用户表内 user_iiqe_records 数组」。

### 2.3 现有 teams / team_members（已确认）

- **删除**现有 `teams`、`team_members` 表，**重新设计**。  
- 每人加入系统即拥有自己的「团队」：**团队与用户一一对应，团队标识与用户 6 位邀请码关联**，6 位邀请码即团队邀请码；邀请树仅通过用户表的邀请关系表达，不再使用独立的 teams/team_members 表。

## 三、数据结构设计

### 3.1 用户表 `users`（扩展）

在现有字段基础上**增加**邀请关系字段（邀请码已存在）。

| 字段 | 类型 | 说明 |
|------|------|------|
| `invitedBy` | string（可选） | **邀请人的邀请码**（invite code）。无则表示未加入任何团队（未填或未绑定邀请人）。 |

- **不新增** `invitedAt`：同门/下属列表的「加入时间」排序统一用用户**注册时间** `createdAt`。  
- 查「谁邀请了我」：`users` 中 `inviteCode === 当前用户.invitedBy` 的用户即为团队长。  
- 查「我的直属下属」：`users` 中 `invitedBy === 当前用户.inviteCode` 的列表，按 `createdAt` 升序。

### 3.2 真实考试记录（用户表内）`user_iiqe_records`

在 `users` 文档中增加字段 **`user_iiqe_records`**，类型为**对象数组**，用于存储该用户**手动提交的真实考试**通过情况，供团队模块统计「合资格」「全牌照」使用；与练习/模拟答题记录无关。

**数组元素结构**（至少包含）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `subjectId` | string | 科目编号，01～05。 |
| `subjectName` | string | 科目名称（如「保险原理及实务」）。 |
| `examTime` | 任意（可选） | 考试时间；默认空。 |
| `passed` | boolean | 是否通过；默认 false。 |
| `passedAt` | 任意（可选） | 通过时间；默认空。 |

**默认值**：新用户创建时，`user_iiqe_records` 初始化为**科目一到科目五共 5 条**，每条对应一个科目；`examTime` 为空，`passed` 为 false，`passedAt` 为空。

- 统计「是否通过某科」时，看该用户 `user_iiqe_records` 中对应 `subjectId` 的那条是否 `passed === true`。  
- 录入/修改由「我的」模块提供入口，用户手动维护；团队模块只读。

### 3.3 删除旧表，不再新增「团队」表

- **删除**：`teams`、`team_members`。  
- **不再新增**与「团队」一一对应的独立表：团队即「以某用户为根的邀请树」，用该用户的 `inviteCode` 作为团队标识即可（团队 ID 与 6 位邀请码关联）。

## 四、核心逻辑说明

### 4.1 邀请关系建立与修改

- **新用户注册**（`user_getUserInfo` 创建新用户时）：  
  - 若传入**邀请码**：校验邀请码对应存在且非本人后，将新用户的 `invitedBy` 设为该邀请码；新用户即加入该邀请人的团队树。  
  - 若**不填邀请码**：`invitedBy` 不填，表示不加入任何团队（无上级，团队页不展示「邀请我的团队长」）。  
- **老用户**：在「**我的**」模块中，用户可**修改「被邀请码」**（即更新 `invitedBy`）以加入新的团队（换上级）；业务上可按需限制修改频率或次数，数据结构上支持按需覆盖 `invitedBy`。

### 4.2 三个统计（团队 / 合资格 / 全牌照）

- **统计范围**：仅当前用户的**全部下属**（邀请树下多层级）。  
  - 下属列表获取：从当前用户 `inviteCode` 出发，递归/迭代查 `invitedBy === 当前层用户 inviteCode`，收集所有下级 openid。  
- **团队**：下属总人数（含多层级）。  
- **合资格**：下属用户中，在其 `user_iiqe_records` 数组内**同时**满足科目 01、03 对应项 `passed === true` 的人数。  
- **全牌照**：下属用户中，在其 `user_iiqe_records` 数组内 01～05 五科对应项均为 `passed === true` 的人数。

### 4.3 邀请我的团队长与所属团队

- **团队长**：当前用户的 `invitedBy` 非空时，查 `users` 中 `inviteCode === 当前用户.invitedBy` 的用户即为团队长。  
- **无上级**（`invitedBy` 为空）：**不展示「邀请我的团队长」整块**。  
- **所属团队列表**（点击团队长进入）：  
  - 成员 = 团队长 + 所有 `invitedBy === 团队长.inviteCode` 的用户。  
  - 顺序：团队长第一，当前用户第二，其余按 `createdAt`（注册时间）升序。

### 4.4 团队成员（直属下属）与下属团队页

- **直属下属列表**：`users` 中 `invitedBy === 当前用户.inviteCode`，按 `createdAt` 升序。  
- **每人展示**：头像、昵称、科目 1～5 通过情况（从该用户 `user_iiqe_records` 数组读取）、该成员的**团队总人数**（其全部下级人数）。  
- **人数与箭头**：若该成员下属总人数 > 0，显示「X人」+ 右箭头并可点击；若为 0，不显示人数与箭头。  
- **下属团队页**：点击某成员后进入「该成员为根」的团队页，**页面结构与现有团队页一致**（顶部三数、可选团队长卡片、其直属成员列表等），仅数据根节点改为该成员。

### 4.5 成员「团队总人数」

- 指该成员在邀请树上的**所有下级**人数（多层级）。  
- 实现：递归/迭代统计；后续若性能需要，可为用户表增加 `subordinateCount` 等缓存字段并在关系变更时维护。

## 五、接口与前端配合（建议）

| 能力 | 建议云函数 | 前端 |
|------|------------|------|
| 团队主页三个数 | `team_getMyStats` | 团队页顶部展示 团队/合资格/全牌照 |
| 邀请我的团队长信息 | `team_getMyLeader` 或与下面合并 | 有上级时展示团队长卡片，点击进入所属团队；无上级不展示整块 |
| 所属团队列表 | `team_getMyLeaderTeam` | 团队长 + 当前用户 + 同门，顺序：团队长、当前用户、按 createdAt 升序 |
| 直属成员列表（含每人下属人数、科目通过） | `team_getMyDirectMembers` | 团队成员列表；无下属不显示人数与箭头 |
| 某成员的下属团队页 | `team_getMemberTeam`(memberOpenid 或 inviteCode) | 与现有团队页结构一致，根节点为该成员 |

- 科目 1～5 通过情况由接口从各用户 `user_iiqe_records` 数组汇总后返回（如 `passedSubjects: ['01','02',...]`），前端渲染圆点。

## 六、与「我的」模块的衔接

- **真实考试通过记录**的维护：在「我的」模块提供入口，用户手动提交/维护；更新对应用户文档中的 `user_iiqe_records` 数组。  
- **修改被邀请码**：在「我的」模块提供「修改被邀请码」入口，更新当前用户的 `invitedBy`，从而加入新团队（换上级）。  
- 具体 UI 与交互在「我的」模块实现时再定，本方案仅约定数据与团队侧只读统计。

## 七、实施时可做的具体改动

1. **数据库**  
   - 在 `users` 增加 `invitedBy`（可选 string）、`user_iiqe_records`（对象数组，结构见上；新用户默认 5 条科目、examTime 空、passed false、passedAt 空）。  
   - 删除集合 `teams`、`team_members`（若存在且确认无其他用途）。

2. **注册/登录**  
   - `user_getUserInfo`：创建新用户时支持入参邀请码，校验后写入 `invitedBy`；不填则不写。

3. **「我的」模块（后续）**  
   - 提供「真实考试结果」录入/编辑入口，更新当前用户文档的 `user_iiqe_records` 数组。  
   - 提供「修改被邀请码」入口，更新 `users.invitedBy`。

4. **团队模块云函数与前端**  
   - 实现 `team_getMyStats`、`team_getMyLeader`、`team_getMyLeaderTeam`、`team_getMyDirectMembers`、`team_getMemberTeam`；统计合资格/全牌照时只读各用户文档的 `user_iiqe_records` 数组。  
   - 团队页与下属团队页统一结构，无上级时不展示「邀请我的团队长」整块。
