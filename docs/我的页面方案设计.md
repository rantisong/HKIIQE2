# 「我的」页面方案设计

基于现有实现与设计稿，对「我的」模块进行方案设计，满足头部展示、数据统计、考试进度、菜单调整及账号设置扩展需求。

---

## 一、需求与现状对照

| 需求项 | 说明 | 现状 |
|--------|------|------|
| 头部账号 | 沿用现有，仅展示头像/昵称/邀请码 | 已实现：`profile-card` 展示头像、昵称、邀请码（当前文案为「邀请码」） |
| 数据统计 | 累计学习、刷题总数、平均正确率（定义见下） | 已有三格统计，但计算口径与需求不一致 |
| 考试进度 | 入口、user_iiqe_records、倒计时、设置通过与通过时间、科目 1～5 默认展示 | 已有「真实考试记录」页（profile-iiqe），数据在 user_iiqe_records |
| 菜单调整 | 删「在线客户」；「真实考试记录」改为「考试进度」；「修改被邀请码」改为「团队邀请码」并入账号设置 | 当前为独立菜单项，无「账号设置」聚合页 |
| 账号设置 | 团队邀请码 + 常驻城市 + 香港身份获取时间 | 仅有 profile-invite（修改被邀请码），无城市/香港身份 |

## 二、页面结构（最终形态）

```
「我的」页
├── 头部账号区（沿用现有）
│   └── 头像、昵称、邀请码
├── 数据统计区（三格）
│   └── 累计学习 | 刷题总数 | 平均正确率
├── 考试进度区
│   └── 标题 +「点击设置提醒」+ 科目 1～5 列表（含考试时间/倒计时/设置考试时间/设置通过）
├── 账号设置（单行入口，点击进入「账号设置」页）
├── 退出登录
```

- **删除**：原「真实考试记录」「修改被邀请码」「在线客服」三个独立菜单项。  
- **新增**：  
  - 本页内「考试进度」区块（列表 + 入口）；  
  - 本页「账号设置」入口；  
  - 新页面「账号设置」，内含：团队邀请码、常驻城市、香港身份。

## 三、详细设计

### 3.1 头部账号（沿用现有，不做调整）

- **展示**：头像、昵称、邀请码。  
- **实现**：保持现有 `profile-card` 与 `setProfileDisplay` 逻辑，仅保证文案统一为「邀请码」即可（若当前已是「邀请码 : xxx」则无需改）。  
- **数据来源**：`user_getProfile` 返回的 `user`（`profile.nickname`、`profile.avatar`、`inviteCode`）。

---

### 3.2 数据统计

#### 重要区分：练习页统计 vs 我的页统计

两处统计口径不同，实现时切勿混淆：

| 维度 | 练习页（首页/试卷列表、报告页） | 我的页（个人中心） |
|------|----------------------------------|---------------------|
| **统计单位** | **完整试卷**：一次完整提交 = 一次考试 | **题目数量**：按题目道数合计 |
| **累计次数 / 练习次数** | 仅当用户**完成整份**模拟试卷或真题试卷时，才算完成一次考试；即 `records` 表中**每条记录** = 1 次。 | 不在此展示；我的页不展示「考试次数」。 |
| **通过率** | 基于**完整提交**：通过次数 / 完成次数（例如单次正确率 ≥70% 计为通过一次）。与「题目级正确率」无关。 | 不在此展示。 |
| **刷题总数** | 不在此展示。 | 所有完整提交中的**题目道数之和**（Σ 每条 record 的题目数）。 |
| **平均正确率** | 不在此展示。 | 所有**题目**中正确数 / 总题数（题目维度的正确率）。 |

**结论**：练习页的「累计通过次数」「通过率」等是**按完整试卷记录**统计的；我的页的「刷题总数」「平均正确率」是**按题目数量**统计的。二者数据源虽都涉及 `records`，但聚合口径不同，不可混用。

---

#### 我的页三指标定义与数据来源

| 指标 | 定义 | 数据来源与计算方式 |
|------|------|---------------------|
| **累计学习** | 用户完成注册、加入系统的天数 | `user.createdAt` 至当前日期的天数（按自然日，不足 1 天按 1 天计）。前端或云函数均可计算。 |
| **刷题总数** | 用户提交题目的数量总和（题目维度） | 即「每次模拟 + 真题」的**题目道数合计**：所有答题记录中**题目道数**之和。`records` 每条 = 一次完整试卷提交，**刷题总数** = Σ 每条 record 的题目数（`results.length`），不是 record 条数。 |
| **平均正确率** | 用户提交题目中正确数 / 用户提交题目总数（题目维度） | 正确数 = Σ 每条 record 的 `results` 中 `isCorrect === true` 的个数；总题数 = 同上。平均正确率 = (正确数 / 总题数) × 100%。与练习页「通过率」（试卷维度）不同。 |

**与现有实现的差异**：

- 当前「我的」页：累计学习用「有答题记录的日期数」、刷题总数为「record 条数」、平均正确率为「各次 score 的平均」。需改为上表口径。
- **数据范围（已确认）**：**模拟 + 真题**的题目提交次数都计入刷题总数与平均正确率。需在模拟提交时同样写入 `records`（或统一走同一套提交逻辑），与真题一并统计。

**实现建议**：

- **方案 A（推荐）**：新增云函数 `exam_getAnswerStats`（或由 `user_getProfile` 扩展返回统计字段）。在云端对当前用户的 `records` 做聚合：  
  - 总题数 = Σ `results.length`（或等价的题目数）；  
  - 正确数 = Σ `results` 中 `isCorrect === true` 的个数。  
  返回 `{ totalQuestions, totalCorrect, recordCount }`，前端再算平均正确率；累计学习可由前端根据 `user.createdAt` 计算，或一并由云函数返回 `memberDays`。
- **方案 B**：前端分页拉全量 `getRecordList` 后自行汇总。实现简单但数据量大时性能差，仅适合记录量很小的场景。

### 3.3 考试进度

- **定位**：用户维护「真实 IIQE 考试」时间与结果的入口；数据存于用户表下 `user_iiqe_records`（与现有团队方案一致）。
- **入口**：在「我的」页增加「考试进度」区块，列表直接展示科目 1～5，每条可点击进入设置/编辑（或在本页内弹层/二级页编辑）。

**展示与交互**：

1. **默认展示科目 1～5**  
   - 进入「我的」时，从 `user_getProfile` 的 `user.user_iiqe_records` 取数；若为空或长度不足 5，前端用默认 5 条（subjectId 01～05 + 默认名称）补全展示，便于用户设定考试时间和结果。
2. **每条科目展示**  
   - 若已设置考试时间：显示「考试时间 : yyyy-MM-dd HH:mm」+ **倒计时 N 天**（以当前时间到 examTime 的天数，过期可显示「已过期」或 0 天）。  
   - 若未设置：显示「点击设置考试时间」或「+ 点击设置考试时间」。  
   - 若已设置通过：可展示通过状态/通过时间（passed、passedAt）。  
   - 左侧蓝色竖条（设计稿）：可用于标识「已设置时间」或「即将考试」等状态（按 UI 规范实现）。
3. **设置提醒**  
   - 标题旁「点击设置提醒」：**暂时仅作展示**，不实现消息提醒或跳转。
4. **编辑**  
   - 点击某科进入现有「真实考试记录」编辑页（即 `profile-iiqe`）或弹层：可设置/修改考试时间、是否通过、通过时间。继续使用 `user_updateIiqeRecords` 写回 `user_iiqe_records`。

**数据结构**（与现有一致，见《团队模块设计方案》）：

- `user_iiqe_records`：数组，每项 `{ subjectId, subjectName, examTime, passed, passedAt }`。  
- 新用户默认 5 条，examTime 为空、passed 为 false、passedAt 为空。

**实现要点**：

- 「我的」页 onShow/loadUserData 时拉取 `getProfile`，取 `user_iiqe_records`，归一化为 5 条后 setData，用于列表渲染与倒计时。  
- 倒计时：前端根据 `examTime` 与当前时间计算天数；若 examTime 为过去则显示「已过期」或 0 天。  
- 保留 `pages/profile-iiqe` 作为「考试进度」的编辑页，路由可从「考试进度」列表项点击进入；菜单名称由「真实考试记录」改为「考试进度」并在本页以区块形式呈现列表 + 入口。

### 3.5 账号设置页（新增）

- **路由**：建议 `pages/profile-settings/index`（或沿用 profile-invite 改造为「账号设置」聚合页）。  
- **入口**：在「我的」页点击「账号设置」进入。  
- **内容**：三项设置并列或分组展示。

| 设置项 | 说明 | 数据存储 | 交互 |
|--------|------|----------|------|
| **团队邀请码** | 即原「修改被邀请码」：填写邀请人邀请码以加入/更换团队 | 用户表 `invitedBy` | 输入 6 位邀请码，调用现有 `user_updateInvitedBy`。文案改为「团队邀请码」或「加入团队（填写邀请人邀请码）」 |
| **常驻城市** | 用户常驻城市（省/市） | 用户表新增 `city`（string，可选） | **省/市二级选择**：采用小程序 `picker` 的 `mode="region"`，选完后仅存储并展示省、市（不存区）；或使用 `multiSelector` + 本地省市数据。需新增/扩展云函数写 `user.city`（建议存如「广东省 广州市」或省+市拼接字符串）。 |
| **香港身份** | 香港身份获取时间 | 用户表新增 `hkIdentityAcquiredAt`（string，可选） | **仅日期**，格式 yyyy-MM-dd；未获得香港身份则日期为空。使用小程序日期选择器（如 `picker mode="date"`）或输入。 |

**用户表扩展**（在现有 `users` 上增加）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `city` | string（可选） | 常驻城市，建议存「省 + 市」如「广东省 广州市」 |
| `hkIdentityAcquiredAt` | string（可选） | 香港身份获取时间，仅日期 yyyy-MM-dd；空表示未获得 |

**接口**：

- 读：`user_getProfile` 已返回完整 user，扩展后直接带出 `city`、`hkIdentityAcquiredAt`。  
- 写：  
  - 团队邀请码：沿用 `user_updateInvitedBy`。  
  - 常驻城市、香港身份：新增云函数 `user_updateProfile` 或 `user_updateSettings`，接收 `{ city?, hkIdentityAcquiredAt? }`，仅更新当前用户对应字段。

## 七、细化实现清单

### 7.1 接口与云函数

| 类型 | 名称 | 说明 |
|------|------|------|
| **扩展** | `exam_submitAnswer` | 支持**模拟 + 真题**均落库。入参增加 `paperType: 'mock' \| 'real'`（可选，默认 `'real'`）。当 `paperType === 'mock'` 时：入参需包含 `subjectId`、`paperTitle`、`answers`、`results`（含 `isCorrect`）、`score`、`timeSpent`；云端不查 real_papers，直接写入 `records`，且每条 record 增加字段 `paperType: 'mock'`。真题逻辑不变，record 可带 `paperType: 'real'` 或省略。 |
| **新增** | `exam_getAnswerStats` | 对当前用户 `records` 聚合（不限 paperType）：**题目维度**——`totalQuestions` = Σ 每条 `results.length`，`totalCorrect` = Σ `results` 中 `isCorrect === true` 的个数。返回 `{ totalQuestions, totalCorrect }`，**仅用于「我的」页**的刷题总数与平均正确率。**注意**：练习页的累计次数、通过率是**试卷维度**（每条 record = 1 次，通过率 = 通过次数/完成次数），不要用本接口或题目维度的数据。 |
| **扩展** | `user_getProfile` | 返回的 user 中增加 `city`、`hkIdentityAcquiredAt`（若已有则无需改）。 |
| **新增** | `user_updateProfile` | 入参 `{ city?, hkIdentityAcquiredAt? }`，仅更新当前用户的 `city`、`hkIdentityAcquiredAt`（可选字段不传则不更新）。 |

### 7.2 数据库

| 集合 | 变更 |
|------|------|
| `users` | 增加字段 `city`（string）、`hkIdentityAcquiredAt`（string，yyyy-MM-dd 或空）。 |
| `records` | 增加字段 `paperType`（string，可选，'mock' \| 'real'），便于统计与筛选；现有真题写入时补上 `paperType: 'real'`。 |

| **utils/api.js** | `submitAnswer` 增加参数 `paperType` 及模拟题所需字段（如 `subjectId`、`paperTitle`、`results`、`score`），传给云函数。 |

### 7.4 常驻城市组件建议

- **方案 A**：`<picker mode="region">`，绑定 `region` 数组（如 `['广东省','广州市','']`），onChange 后只取前两项拼接为 `city` 展示与存储（不存区）。  
- **方案 B**：使用 `multiSelector` + 本地 JSON 省市区数据（仅加载省、市两级），数据量可控且可严格省/市两级。

### 7.5 香港身份展示与存储

- 存储：`hkIdentityAcquiredAt` 为 string，格式 `yyyy-MM-dd`，空字符串表示未获得。  
- 展示：列表/详情可显示「xxxx-xx-xx」或「xxxx年xx月」；未获得时显示「未设置」或「未获得」。

以上清单可直接用于开发排期与实现；若将「团队邀请码」保留为独立页 profile-invite，则账号设置页中可放「团队邀请码」入口跳转至 profile-invite，无需在 profile-settings 内嵌完整表单。
